
HTML, CSS, JavaScript만 사용해서 동작하는 **옷장 관리 웹서비스 MVP**를 구현해라.  
백엔드 없이도 동작하는 **정적 웹앱 수준의 MVP**로 만들고, 저장은 `localStorage`를 사용해라.

서비스의 핵심은 **날씨 추천이 아니라 옷장 속 옷을 정리하고 관리하는 것**이다.  
날씨 API는 **부가 기능**으로만 간단히 연동. 
기능은 단순하지만 실제로 사용할 수 있는 수준의 MVP로 구현해라.

---
1. 프로젝트 목표
사용자가 자기 옷 사진을 업로드하면,

옷을 종류별/키워드별로 정리하고,

날씨에 맞는 추천 코디를 자동으로 보여주며,

사용자가 > < 버튼으로 추천 아이템을 넘겨가며 마음에 드는 조합을 골라

오늘의 코디를 저장할 수 있게 한다.

저장한 코디는 별도의 화면에서 확인, 수정, 삭제할 수 있어야 한다.
---

## 2. 구현해야 할 핵심 기능

### A. 옷 업로드 기능
- 사용자가 자기 옷 사진을 업로드할 수 있어야 한다.
- 업로드 시 옷 정보도 함께 입력할 수 있어야 한다.
- 입력 항목은 아래처럼 단순하게 한다.
  - 옷 이름
  - 종류: 상의 / 하의 / 겉옷 / 원피스 / 신발 / 악세사리
  - 키워드 태그
  - 메모
- 사진은 업로드 후 미리보기가 보여야 한다.
- 업로드한 옷은 옷장 목록에 카드 형태로 표시되어야 한다.

### B. 키워드별 정리 기능
- 옷마다 키워드를 여러 개 붙일 수 있어야 한다.
- 예:
  - 얇은
  - 두꺼운
  - 반팔
  - 긴팔
  - 여름용
  - 겨울용
  - 캐주얼
  - 포멀
  - 데일리
- 사용자가 키워드를 선택하면 해당 키워드를 가진 옷만 필터링해서 볼 수 있어야 한다.
- 예를 들어 `얇은` 키워드를 누르면 얇은 옷만 모아서 보여준다.

### C. 착용 빈도 관리
- 사용자가 옷을 “입음” 처리할 수 있어야 한다. 탭 1에서 오늘의 코디 선택 버튼을 누르면 입음처리 할 수 있다.
- 옷을 입음 처리하면 착용 횟수가 1 증가한다.
- 착용 횟수를 기준으로 아래를 보여줘라.
  - 가장 많이 입은 옷
  - 거의 안 입은 옷
  - 오래 안 입은 옷
- 아주 복잡한 통계는 필요 없고, MVP답게 간단한 요약만 있으면 된다.

### D. 코디 저장 기능
- 단순한 옷 추천이 아니라, 사용자가 직접 조합한 코디를 저장할 수 있어야 한다.
- 코디는 아래 항목을 조합할 수 있다.
  - 상의
  - 하의
  - 겉옷
  - 악세사리
- 사용자가 코디 이름을 직접 입력해서 저장하게 한다.
- 저장한 코디는 “내가 좋아한 코디” 또는 “저장한 코디” 목록에서 다시 확인할 수 있어야 한다.
- 이 기능은 저장/조회 중심으로 간단히 구현한다.
- 좋아요, 즐겨찾기 같은 기능이 있으면 좋지만 필수는 아니다.

### E. 날씨 API 연동
- 날씨 API는 메인 기능이 아니라 보조 기능이다.
- 오늘 기온과 날씨 상태를 보여주고, 옷장에 등록된 옷 중에서 간단히 추천해라.
- 추천 로직은 단순하게 구현해도 된다.
  - 기온이 높으면 얇은 옷, 반팔, 여름용 키워드 우선
  - 기온이 낮으면 긴팔, 두꺼운 옷, 겉옷 우선
  - 비가 오면 방수나 겉옷 관련 옷 우선
- 중요한 점은 **사용자가 실제로 등록한 옷만 추천**해야 한다는 것이다.

사용자가 지역을 입력하면 그 지역의 날씨를 api를 통해 가져온다.

### 옷장 목록 화면 기능
옷장 화면에서는 사용자가 업로드한 모든 옷을 확인할 수 있어야 한다.

포함 기능
옷 카드 목록
키워드 필터
종류별 필터
착용 횟수 표시
많이 입은 옷
최근에 안 입은 옷

---

## 3. 추천 로직은 단순하게
MVP이므로 복잡한 AI 모델은 쓰지 말고, 규칙 기반으로 구현해라.

예시:
- 기온 28도 이상: `반팔`, `얇은`, `여름용` 우선
- 기온 18~27도: `데일리`, `캐주얼`, `얇은 겉옷` 우선
- 기온 17도 이하: `긴팔`, `두꺼운`, `겉옷`, `겨울용` 우선
- 비/눈: 악세사리 '우산' 필수

## 4. 화면 구성
전체적으로 **밝고 산뜻한 파스텔톤**으로 디자인해라.  
 **연한 민트, 연두, 크림, 부드러운 핑크** 계열을 활용해라.  
무겁지 않고 깔끔한 카드형 UI로 구현해라.

2. 최소 화면 구성

화면 1. 메인 대시보드
- 오늘 날씨 표시
- 오늘 추천 코디 표시
- 좌우 버튼으로 옷 아이템을 넘기며 코디 선택
- 오늘의 코디 선택/ 코디 즐겨찾기 추가 두 가지 버튼을 구현한다.
오늘의 코디 선택: 입음 처리 횟수가 1회 증가
즐겨찾기 추가 : 즐겨찾기 탭에서 내가 즐겨찾기 한 코디를 볼 수 있게 한다.
- 추천 결과 영역 오른편에 aside 형태의 조합 패널 배치, 이곳에서 코디 선택 가능


화면 2. 옷장 목록 화면
- 업로드한 옷 카드 목록
- 키워드 필터
- 착용 횟수 요약
- 가장 많이 착용한 옷, 최근에 안 입은 옷 표시


화면 3. 옷 업로드 화면 또는 모달
- 사진 업로드
- 이름, 종류, 키워드, 메모 입력
- localStorage 저장


화면 4. 저장한 코디 목록 화면
- 저장한 코디 리스트
- 수정
- 삭제

3. 메인 대시보드의 핵심 UI 요구사항
메인 대시보드에는 날씨 기반 추천 영역과 함께,
오른쪽 aside에 가상의 표(table-like layout) 를 만든다.
중요한 것은 각 칸에 카테고리별 옷 리스트가 하나씩 표시되고,
사용자가 < > 버튼으로 그 리스트를 순회할 수 있어야 한다는 점이다.

1열 1행: 모자/악세사리 리스트
1열 2행: 상의 리스트
2열 2행: 겉옷 리스트
1열 3행: 하의 리스트
2열 3행: 기타 악세사리 리스트

그리고 각 칸은:
사진 1장만 표시
<, > 버튼으로 이전/다음 옷 이동
현재번호/전체개수 표시
날씨 조건에 맞는 아이템만 후보로 보여줌
이 이외의 기능은 넣을 필요 없다.

각 칸에는 해당 카테고리의 옷이 한 번에 하나만 표시된다.
옷 사진 좌우 옆에 작게 < > 버튼을 두어,
같은 카테고리 내의 아이템을 순회하도록 한다.
예:
하의 칸에서 "긴 바지 / 밝은 옷" 조건을 공유하는 하의 리스트가 있을 경우, 한 장씩 보여주고 버튼으로 넘기면서 비교할 수 있어야 한다.
단, 각 표의 칸에는 옷의 사진과 좌우의 '<' '>' 그리고 날씨의 따라 추천된 각 카테고리의 옷의 전체개수와 현재 옷의 위치(예: 상의를 6벌 추천했다면 첫번째 옷은 1/6, '>'로 넘긴 옷은 2/6이 된다)만을 표시한다.

사용자가 마음에 드는 코디를 선택했다면 두 가지 버튼을 누를 수 있다.
오늘의 코디 선택: 입음 처리 횟수가 1회 증가
즐겨찾기 추가 : 즐겨찾기 코디에 추가된다. 즐겨찾기 탭에서 내가 즐겨찾기 한 코디를 볼 수 있게 한다.

## 5. 구현 조건
- HTML, CSS, JavaScript만 사용해라.
- 프레임워크는 사용하지 말고 순수 바닐라 JS로 구현해라.
- 데이터는 `localStorage`에 저장해 새로고침해도 유지되게 해라.
- 파일 구조는 단순하게 나눠라.
  - `index.html`
  - `style.css`
  - `script.js`
- 반응형으로 만들어 모바일에서도 보기 좋게 해라.
- 코드가 너무 과하지 않게, 바로 실행 가능한 수준으로 작성해라.
